NERDSS · serial pairwise search

How the cell grid is built, and whether a tree should replace it

The serial bimolecular search bins molecules into a uniform Cartesian grid over the simulation box and walks a 13-neighbour stencil. This audit measures what that grid actually delivers on every system geometry NERDSS supports — and finds that on boxes thinner than four interaction lengths it silently misses reacting pairs, while on three other geometries its own guard rails inflate the work by 12× to 98×.

Update — all eight fixes have landed

All eight ranked fixes are implemented on nerdss-optimized, one commit each, each verified against its own parent. Ten of the thirteen benchmark cases are 1.2× to 3.1× faster; every commit that changes the random stream does so only on the grids it was meant to change, and each is statistically indistinguishable from its parent (largest |z| = 1.24 over 12–28 seeds). Numbers are in benchmarks/nerdss_optimized/RESULTS.md §19 and §20.

Fix 8 changed the conclusion about spheres rather than confirming it — see what the sphere was actually spending its time on.

01 · The method in one paragraph

SimulVolume::create_simulation_volume() lays a single uniform Cartesian grid over the axis-aligned bounding box Membrane::waterBox. Every cell gets a half-neighbour list — 13 of the 26 surrounding cells, forward and up — so each pair is offered once. The grid is built once, at parse time, and never rebuilt. Every timestep, update_memberMolLists() re-bins all molecules by centre of mass in O(N), and the pair loop sweeps all cells, offering every same-cell and stencil-neighbour pair to check_bimolecular_reactions().

Three structural facts follow from that description and matter for everything below. There is exactly one neighbour-list builder, create_cell_neighbor_list_cubic() — no geometry ever gets a decomposition of its own, spheres included. Binning is on molecule COM while the reaction criterion is interface-to-interface, which is why the cutoff has to absorb both COM→interface arm lengths. And the stencil does not wrap, which is consistent only because xBCtype = periodic is parsed but never implemented — every propagation path in reflect_dispatch.cpp reflects.

The serial pair loop is the inline copy at EXEs/nerdss.cpp:849. The extracted function measure_separations_to_identify_possible_reactions() is the MPI path only; the two have diverged (the serial copy handles hasCompartment, the extracted one handles isGhosted).

3D box, well proportioned works

The design case: clathrin, mem_localization, implicit_lipid. Cells land within 6% of rMaxLimit and over-inclusion sits at or under the 6.4× floor. Nothing to fix.

3D box, large — the 30-cell cap binds 2× cells, 12× work

rev_3D wants ⌊940/16.7⌋ = 56 cells per side and gets 30, so cells come out 1.88× too wide and over-inclusion doubles to 11.8×. Same story in rev_3Dto2D. The cap exists only because the pair loop sweeps every cell, which the branch's own occupiedSubCells list already makes unnecessary.

3D box, small — the grid barely helps 4.1× over brute force

michaelis_menten is a 144 nm box against a 33.9 nm cutoff: 4 cells per side, 84% of them occupied, and the 3×3×3 stencil covers 42% of the entire box. The grid buys a factor of 4 over checking all 6 786 pairs. That is the correct outcome — there is nothing to decompose — but it is worth knowing the machinery is nearly idle here.

Quasi-2D membrane structurally unsound in z

Membrane-bound molecules all land in one z-row (zItr is inverted and clamped), so 1 − 1/nz of the grid is dead by construction. rev_2D is the extreme: a 1000·1000·10 nm slab against a 5.79 nm cutoff gives cells of 33.3 · 33.3 · 2.5 nm. In-plane the 30-cap makes them 5.75× too wide — 52× over-inclusion. In z they are 2.5 nm against a 5.79 nm cutoff, which is unsound; it is harmless here only because every molecule sits in the same row.

A second-order effect: rMaxLimit is the maximum over all reactions, including 3D ones with large Dtot. A membrane system therefore sizes its cells for the fastest solution-phase reaction it contains.

Sphere now indexed by latitude and longitude

Membrane::create_water_box() sets waterBox to the (2R)³ bounding cube and the same cubic grid is laid over it. For surface-bound molecules only the shell cells can ever be occupied — a fraction πh/(2R) of the box. On the sphere case that is 1 257 reachable cells of 8 000 (15.7%); 448 are actually occupied, and the remaining 94.4% are swept every timestep for nothing.

There is also a metric mismatch: get_distance() measures surface pairs by geodesic arc length while the grid bins on Cartesian coordinates. Arc ≥ chord, so the grid stays conservative — no pairs are lost — but it over-includes on small spheres where curvature is high.

sphere offers nothing at all: its only reaction binds A to an implicit lipid, so fix 6's type mask discards every pair before the search reaches it. On the R=70 sphere, 96.4% of what is offered has a molecule off the surface, which a shell index does not touch. And a sampling profile of that model puts 11655 of 11662 samples inside determine_2D_bimolecular_reaction_probability → create_survMatrix/create_pirMatrix → integrator → Bessel j0/y0/j1/y1. That is 2D reaction-table construction; it runs only for pairs already within Rmax, so no neighbour structure can reduce it.

This is the same lesson as §5, arriving one level down. The grid was the wrong structure for the sphere, and fixing it was still the wrong thing to optimise, because the sphere's cost was never in the search. What the index earns its place for is spheres large enough that the (2R)³ bounding cube exceeds the sub-volume budget and the interior starts taking resolution from the shell — around R = 2000 nm against a 30 nm range.

One measurement is worth keeping for its own sake. The first version activated for any sphere, and that made sphere 9% slower while staying bitwise identical: 448 surface molecules rebinned every step, an acos and an atan2 apiece, to fill an index whose every pair was then discarded. The index now also requires that some two explicit molecules can react with each other — the same "do not index what cannot react" rule as fix 6, applied to the whole structure rather than to a pair.

Compartment 98× over-inclusion

hasCompartment does not touch the grid; compartment binding is a per-molecule check. What this case exposes instead is the maxPairs downscaler. With N = 100 the budget is max(4000, 5000) = 5 000 cells, the initial 30³ = 27 000 blows it, and the loop shrinks the grid to 17·17·8 — cells of 58.8 · 58.8 · 125 nm against a 28.4 nm cutoff. The 2:1 anisotropy is the 2·scale divisor on z. Over-inclusion reaches 97.6×, the worst measured, on the case whose molecule count triggered the guard meant to make it faster.

1D fiber unrepresented

Complexes with onFiber lie along x and are binned by the ordinary 3D box grid, occupying a one-cell-wide line through it. No fiber-aware decomposition exists.

04 · The correctness gap

When Lz < 4·rMaxLimit, the stencil cannot reach every reacting pair

z = std::max(4, ...) forces four z-cells regardless of box thickness, and check_dimensions() re-applies the same floor rather than correcting it. Below Lz = 4·rMaxLimit the cells become thinner than the interaction range, and the ±1 stencil stops covering it. Pairs two cells apart in z are never offered to check_bimolecular_reactions() at all.

Measured on the rev_3D model (2 000 molecules, rMaxLimit 16.70 nm, 1 000 steps, 19 snapshots) with the box thickness varied and every pair counted by brute force:

The boundary is exactly where the arithmetic predicts: zero missed pairs whenever cell size ≥ rMaxLimit, non-zero the moment the floor forces it below. This is a systematic bias in the association rate, not a statistical one — and it is silent.

It is not confined to thin boxes. Applying the fix turned up a second case in the benchmark suite: trimer, a cubic 118.41 nm box against a 37.58 nm range. floor(118.41 / 37.58) = 3, so the floor forced four z cells of 29.60 nm — thinner than the range, in a cubic box. Reconstructing both grids over 101 trajectory frames and 454,619 in-range pairs: the old 3×3×4 grid could not reach 0.398% ± 0.009% of them; the new 3×3×3 grid reaches all of them. That is below what an equilibrium comparison resolves — 28 seeds put the seed-to-seed scatter at 2.7% against a 0.4% mechanism — so the pair count, not the copy numbers, is what carries the claim.

Pre-existing. Dimensions() and check_dimensions() are byte-identical on master; the nerdss-optimized branch neither introduced nor fixed it.

05 · Would a KD-tree fit better?

Verdict

No. Keep the domain decomposition — and fix its parameterisation.

A tree would recover at most the over-inclusion factor, capped at ~5× by the cell list's own 6.4× floor, while costing O(N log N) rebuilds and O(N2/3+k) queries. The measured losses are five to six times larger than that and every one of them lives somewhere a tree does not reach.

The asymptotics favour the grid

Every coordinate changes each timestep, so both structures are rebuilt each step. The grid build is an O(N) counting sort; a balanced KD-tree is O(N log N), and range search in 3D is O(N2/3 + k) per query, not O(log N). At roughly uniform density a uniform cell list is the textbook optimum for a fixed-cutoff neighbour problem, which is why MD codes use it. Rebinning already costs almost nothing here — never more than 5% of total runtime in any case measured.

Enumeration is not where the time goes

The pair loop is 36–99.8% of runtime, but the cost inside it is per-candidate physics, not per-candidate lookup: the type scan, the bound-partner scan, freelist × rxnPartners × freelist, find_which_reaction(), then the 2D/3D probability machinery. In rev_2D and gagsphere the pair loop is over 99% of the run and the enumeration inside it is a rounding error. Sweeping every cell — the one part a tree removes for free — costs 2–6% of total runtime:

Read the last three rows. In mem_localization the grid offers 164 972 pairs per step and 699 survive the type filter — 3 755 of the 3 955 molecules are lipids that cannot react with each other, and the grid dutifully enumerates every lipid–lipid pair in the stencil. In implicit_lipid and sphere the only reaction is with the implicit lipid, so not one of the pairs the search produces can ever react: the entire pairwise machinery runs to completion producing nothing, 11.9 M and 1.7 M times over.

A KD-tree over the same point set enumerates exactly the same useless pairs. Four losses, none of them structural:

  • Type-blindness. Fixed by indexing per reacting type, or by keeping non-reacting species out of the search entirely — a change to what is indexed.
  • One global radius. rMaxLimit is the max over every reaction, so a system with one fast 3D reaction sizes its cells for that reaction alone. A tree could query per-pair radii — but so can a grid, with per-type cell sizes.
  • COM binding vs interface reaction. rMaxLimit carries both COM→interface arms (20 nm of clathrin's 33.7). Indexing interfaces rather than molecule COMs shrinks the radius to σ + 3√(6DΔt) directly. Orthogonal to the structure.
  • Guard rails that override the physics. The 30-cap, the maxPairs downscaler, the z floor. Roughly thirty lines, and they cost more than a tree would recover.

Where a tree genuinely would help — and what beats it

The one honest advantage is adaptivity to density that does not fill its bounding box, which is exactly the sphere and membrane cases: 94.4% of the sphere grid can never hold anything, and on the membrane two-thirds of the molecules sit in a thirtieth of the volume. But the fix for “the bounding box is mostly empty” is a sparse cell list — occupied cells in a hash keyed by (i,j,k) — which keeps O(N) build and O(1) query and costs nothing when the box is full. A tree pays log N and pointer-chasing for the same adaptivity. For the sphere specifically the physically right answer is a surface decomposition (lat–long bands or HEALPix on the shell) for OnSurface complexes, with the Cartesian grid kept for the interior. That beats both.

One more practical count against the tree in this codebase: molecules are created and destroyed mid-step, and several sites mutate memberMolList in place — check_dissociation.cpp:164, check_for_unimolecular_reactions_population.cpp:100, create_molecule_and_complex_from_rxn.cpp:103. A cell list supports O(1) insert and erase. A KD-tree does not.

07 · Two defects found on the way

Duplicate cell membership after any creation reaction this branch only

clear_member_lists() (commit 0784dd8) clears only the cells listed in occupiedSubCells. But create_molecule_and_complex_from_rxn.cpp:103 pushes straight into memberMolList without registering the cell. A molecule created by zeroth-order or unimolecular creation therefore lands in an untracked cell, survives the next clear, and is added again by the re-binning pass — so it is paired twice, and that cell is never cleared again.

Reproduced on VALIDATE_SUITE/create_destroy: untracked non-empty cells and duplicate members appear from simItr 1. master is unaffected — it clears every cell unconditionally.

Fix: have the creation path register its cell in occupiedSubCells, or track occupancy with a per-cell flag rather than a separate list.

rMaxLimit stays 0 for unimolecular-only models

set_rMaxLimit() only falls back to 40 nm when forwardRxns is empty. A model with forward reactions but none bimolecular leaves rMaxLimit = 0, and Dimensions() then divides the box length by it — which is the documented infinite “CELL PAIR MAX EXCEEDED” loop already recorded against unimolecular_reverse in known_broken.tsv.

Fix: guard on the value, not the container — if (params.rMaxLimit <= 0.0) params.rMaxLimit = 40.0;

Measured by adding temporary counters to EXEs/nerdss.cpp, src/reactions/check_bimolecular_reactions.cpp and src/reactions/get_distance.cpp: per-cell occupancy and stencil pair counts sampled every 50 steps, a brute-force O(N²) ground-truth pair count behind an environment flag, and std::chrono spans around the rebinning and pair loops. Sample counts per case range from 7 to 599 snapshots. All instrumentation has been reverted; the working tree is clean and bin/nerdss is rebuilt from unmodified sources.
